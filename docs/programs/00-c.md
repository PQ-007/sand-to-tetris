C Shard is a language we designed together, to show that a language is something you can make: tokens, a syntax tree, a type checker, VM code. **C** is a real language that people use every day, and on this machine it compiles straight to assembly, with no VM in between. Every game in this section except Bitfall is written in it.

## Straight to assembly

The C Shard compiler turns `s = s + i;` into VM commands, and the translator turns each command into a few instructions that push and pop the stack: 14 instructions for that one line. The C compiler (`toolchain/c`, the crate `s2t-c`) keeps values in registers while it works out an expression, so `s += i;` becomes 4:

```
LOAD  r0, [r6 + 1]   ; s
LOAD  r1, [r6 + 2]   ; i
ADD   r0, r0, r1
STORE r0, [r6 + 1]
```

It uses the registers like this: r0 to r4 hold values while an expression is worked out, **r5 is always 0** (so a global near the start of RAM is one `LOAD r0, [r5 + n]`), r6 is the stack pointer, and r7 holds the return address. A function's locals sit in its frame at `[r6 + n]`. Multiplying by a constant becomes shifts and adds; only multiplying or dividing two variables calls a small routine.

The ISA has no overflow flag, so comparing two signed numbers takes a trick: flip both sign bits, then compare as unsigned. That costs three extra instructions, which is why the games often count with pointers or unsigned numbers in their busiest loops.

## C on a 16-bit machine

Everything is one 16-bit word: `char`, `short`, `int` and pointers. `sizeof(char)` is 1 and so is `sizeof(int)`; C allows a "byte" to be 16 bits. There is no `float`: games use **[[fixed point|fixed-point]]** instead, an `int` holding a value times 16 or 256, so a ball can move 1.5 pixels a frame as 24 sixteenths. There is no `long` either. Structs, unions, arrays, pointers, function pointers, `switch`, `goto` and the preprocessor's `#define` and `#if` all work.

## machine.h

`#include <machine.h>` gives a library written in C and compiled with your program; whatever you don't call is left out.

| Function | Does |
|---|---|
| `clear()`, `plot(x, y, on)`, `fill_rect(x, y, w, h, on)`, `draw_line(…)` | pixels, rectangles and lines |
| `draw_sprite(x, y, rows, h)` | a picture up to 16 pixels wide, a word per row |
| `draw_text("HI", col, row)`, `draw_int(n, col, row)` | text in the OS's 3 × 5 font |
| `use_buffer()`, `show()` | draw into a copy of the screen, then show it at once |
| `key()`, `wait_key()`, `ticks()`, `next_frame()` | the keyboard and the 60-a-second timer |
| `rand()`, `rand_below(n)`, `sin256(a)`, `isqrt(v)` | random numbers and a little math |

Drawing straight onto the screen while you erase and redraw makes the picture flicker. Drawing into a copy and showing it all at once is **[[double buffering|double-buffering]]**; every game here does it.

## Write your own

On the Machine page, choose **C** and the example "Text, a key and a dice", then change it. The page shows the assembly your program became, with ▶ at the instruction running now, and errors point at your C lines. `docs/C.md` lists everything the compiler takes.

<aside class="summary">

## What it shows

- A compiler that keeps values in registers makes code several times shorter than one that goes through a stack machine.
- On a 16-bit machine without floating point, fractions are fixed point: whole numbers with a scale.
- A library is just more code compiled with yours; the screen is memory, so drawing is storing.

</aside>

すべてがそろいました。トランジスタでできたゲートでできた CPU、アセンブラ、仮想マシン、言語、そしてオペレーティングシステム。**Bitfall** は、そのすべての上で動くゲームです。このコースのために設計した落ちものパズルで、ピースが井戸の中へ落ちていき、埋めた行が消えます。C Shard で約 360 行、`games/bitfall.shard` に書かれているので、それが実行する命令はどれも、あなたが書いたコンパイラ、トランスレータ、アセンブラを通り、あなたが書いた OS の上に載っています。

## 設計したゲーム

あなたが望んだのはクラシックなテトリスでした。それは独自のピースと名前をもつ特定のゲームなので、代わりにあなたのルールはそのままに、ピースと名前を私たち独自のものにしました。

| 問い | 選んだもの | 理由 |
|---|---|---|
| 消去 | 埋まった行が消え、**ターゲット**のパターンと一致する行はボーナス付きで消える | ターゲットがあると、どの行も読む価値のある 2 進数になる |
| 盤面 | 4 ピクセルのセルが 10 × 20 | 両脇に、スコア、次のピース、ターゲットを置く余地がある |
| ピース | **ランダムに育てる**:つながった 3〜5 個のセル、毎回違う | 決まった組がないので、どのゲームも新しい |
| 名前 | Bitfall | ビットが、ビットの行の中へ落ちる |

矢印でピースを動かしたり回したりし、下でピースを少し下げ、スペースで一気に落とします。完全なルールは `docs/GAME.md` にあります。

## 盤面は数である

盤面の各行は 10 ビットの数として蓄えられ、いちばん左のセルがビット 9 です。この一つの決定で、ゲームのほとんどが数行のビット演算になります。埋まった行は 1023、1 のビットが 10 個です。ターゲットは 1 から 1022 までの数にすぎず、脇に 2 進数で表示され、行がそれと等しくなるとボーナス付きで消えます。

<bitrow-demo></bitrow-demo>

ピースも同じように、5 ビットの行が最大 5 つとして蓄えられます。ピースの行を列 x の位置にずらすのは `(row << 5) >> x` で、あとは次のとおりです。

- ピースのどれかの行と、その下の盤面の行の AND が 0 でなければ、ピースは盤面と**衝突**しています。1 行につき 1 命令の **[[衝突判定|collision-detection]]** です。
- ピースの**固定**は、ピースの各行を盤面へ OR することです。
- 行の**消去**は、その上のすべての行を一つ下へコピーすることです。

## ランダムに育てるピース

新しいピースは、5 × 5 の正方形の真ん中のセル一つから始まります。それから、ゲームはピースのセルをランダムに一つと方向をランダムに一つ選び、そこの隣が空いていれば加えます。これを、ピースのセルが 3、4、5 個になるまで続けます。すべては OS の乱数が決め、最初のキー押下がタイマーからそのシードを設定したので、二つのゲームが同じピースを見ることはありません。最後に、ピースは正方形の左上へ移されます。

ピースを時計回りに 4 分の 1 回転させると、(行 y、列 x)のセルは(行 x、列 h − 1 − y)へ移ります。h はピースの高さです。回したピースが収まらなければ、ゲームはあきらめる前に左右に 1 セルか 2 セルずらしても試すので、壁の隣でもピースを回せます。

## ゲームループ

ゲームは、ピースが一番上に出られなくなるまで回る一つのループです。これが **[[ゲームループ|game-loop]]** です。

1. キーを読む。前回から変わっていれば、それに応じて動かす、回す、落とす。変化のときだけ反応するので、キーをどれだけ長く押していても、1 回の押下でピースは 1 回動きます。下を押し続けると、わざと繰り返します。
2. タイマーを読む。ピースが落ちる時刻なら 1 行下げ、下げられなければ固定する。
3. 変わったものだけを描く。ピースの古いセルを消し、新しいセルを点ける。固定したあとは、盤面と脇のパネルを描き直す。

落下は、あなたがメモリマップに加えたフレームカウンタ、`ticks()` で時間を計るので、ゲームはレベルによって速くなり、シミュレーションの速さで変わることはありません。

## いちばん下まで

Bitfall が動いているときに右矢印を押し、それがあなたの作ったすべてを通っていくのを追ってみましょう。

<line-figure name="exploded"></line-figure>

| レイヤー | 起きること |
|---|---|
| キーボード | マシンのページがアドレス 0x6000 に 130 を置く |
| C Shard | `key()` が 130 を返し、`try_move(1, 0)` が AND で盤面を調べる |
| OS | `fill_rect` が、ワード単位で古いセルを消して新しいセルを点ける |
| VM | `push`、`load`、`and`、`jumpifnot`、`call`:あなたが翻訳したスタックマシン |
| アセンブリ | `LOAD`、`AND`、`JZ`:あなたのアセンブラがワードに符号化したもの |
| CPU | 制御ユニットが各ワードをデコードし、ALU が AND を行い、PC がジャンプする |
| メモリ | RAM が盤面の 20 行を保持し、画面のワードがピクセルを点す |
| ゲート | どの演算も、NAND、NOR、NOT のゲートと、それで作った加算器やマルチプレクサ |
| トランジスタ | どのゲートも、オンとオフを切り替える NMOS と PMOS のトランジスタ |
| シリコン | どのトランジスタも、ゲートの電圧で開くチャネルをもつ、ドープされたシリコン |

マシンのページは CPU の高速モデルを動かします。あなたの `cpu` と `computer` のレベルがチェックされるのと同じ振る舞いなので、1 秒に何百万命令でも問題ありません。エディタでは、高速モデルは一致チェックで両者の一致が証明されたあとでだけ、あなたの設計の代わりになります。

## 落ちものの由来

最もよく知られた落ちものパズルはテトリスです。アレクセイ・パジトノフが 1980 年代半ば、ソビエト科学アカデミーのドロドニーツィン計算センターで、PDP-11 のソビエト製の複製であるエレクトロニカ 60 の上で書きました。それはパズルビデオゲームの市場を生み出す助けになりました[@tetris-origin]。Bitfall は同じジャンルに属し、独自のピース、ルール、名前をもっています。

## 作ったもの、学んだこと

**作ったもの:** Bitfall。あなた自身の言語で書かれ、あなた自身の OS の上で、あなた自身のツールチェーンでコンパイルされ、トランジスタから作ったコンピュータの上で動くゲーム。砂からゲームまで。

**学んだこと:**

- データをどう蓄えるか(行を数として)を選ぶことで、ゲームのルールを数個のビット演算に変えられる。衝突には AND、固定には OR、消去には比較。
- ランダムな形は、隣を一つずつ加えて育てられる。回転は小さな座標の式である。
- ゲームはループである。入力を読み、タイマーに合わせて状態を更新し、変わったものを描く。
- コンピュータのどのレイヤーも、一つ下のレイヤーの上に築かれた小さな考えであり、あなたはそのすべてを作った。

**次へ:** 遊ぶ、ルールを変える、あるいは C Shard や C で自分のゲームを書く。その下にある機械は、どの部分もあなたのものです。

</aside>

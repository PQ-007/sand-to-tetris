C Shard は、言語は自分で作れるものだと示すために一緒に設計した言語です。トークン、構文木、型チェッカー、VM コード。**C** は人々が毎日使っている本物の言語で、このマシンでは VM を挟まずにアセンブリへ直接コンパイルされます。このセクションのゲームは、Bitfall を除いてすべて C で書かれています。

## アセンブリへ直接

C Shard のコンパイラは `s = s + i;` を VM コマンドに変え、トランスレータが各コマンドを、スタックにプッシュしたりポップしたりする数個の命令に変えます。その 1 行で 14 命令です。C のコンパイラ(`toolchain/c`、クレート `s2t-c`)は、式を計算する間、値をレジスタに置いておくので、`s += i;` は 4 命令になります。

```
LOAD  r0, [r6 + 1]   ; s
LOAD  r1, [r6 + 2]   ; i
ADD   r0, r0, r1
STORE r0, [r6 + 1]
```

レジスタの使い方は次のとおりです。r0 から r4 は式を計算する間の値を保持し、**r5 は常に 0**(だから RAM の先頭近くのグローバル変数は `LOAD r0, [r5 + n]` 一つで読めます)、r6 はスタックポインタ、r7 は戻りアドレスを保持します。関数のローカル変数はそのフレームの `[r6 + n]` にあります。定数による掛け算はシフトと足し算になり、変数どうしの掛け算や割り算だけが小さなルーチンを呼びます。

ISA にはオーバーフローフラグがないので、符号付きの数どうしを比べるには工夫が要ります。両方の符号ビットを反転してから、符号なしとして比べるのです。命令が 3 個余分にかかるので、ゲームはいちばん忙しいループでは、ポインタや符号なしの数で数えることがよくあります。

## 16 ビットマシンの上の C

すべてが 16 ビットのワード一つです。`char`、`short`、`int`、ポインタ。`sizeof(char)` も `sizeof(int)` も 1 です。C では「バイト」が 16 ビットでもかまわないのです。`float` はありません。ゲームは代わりに **[[固定小数点|fixed-point]]** を使います。値に 16 や 256 を掛けて保持する `int` で、ボールは 1 フレームに 1.5 ピクセル、つまり 16 分の 24 だけ動けます。`long` もありません。構造体、共用体、配列、ポインタ、関数ポインタ、`switch`、`goto`、プリプロセッサの `#define` と `#if` はすべて使えます。

## machine.h

`#include <machine.h>` は、C で書かれ、あなたのプログラムと一緒にコンパイルされるライブラリを与えます。呼ばないものは含まれません。

| 関数 | すること |
|---|---|
| `clear()`、`plot(x, y, on)`、`fill_rect(x, y, w, h, on)`、`draw_line(…)` | ピクセル、長方形、直線 |
| `draw_sprite(x, y, rows, h)` | 幅 16 ピクセルまでの絵。1 行に 1 ワード |
| `draw_text("HI", col, row)`、`draw_int(n, col, row)` | OS の 3 × 5 フォントの文字 |
| `use_buffer()`、`show()` | 画面の写しに描いてから、一度に表示する |
| `key()`、`wait_key()`、`ticks()`、`next_frame()` | キーボードと、1 秒に 60 回のタイマー |
| `rand()`、`rand_below(n)`、`sin256(a)`、`isqrt(v)` | 乱数とちょっとした数学 |

消しては描き直しながら画面に直接描くと、絵がちらつきます。写しに描いて、それを一度に表示するのが **[[ダブルバッファリング|double-buffering]]** です。ここのゲームはどれもそうしています。

## 自分で書く

マシンのページで **C** と例「Text, a key and a dice」を選び、書き換えてみましょう。ページには、プログラムが変換されたアセンブリが、今実行中の命令に ▶ を付けて表示され、エラーはあなたの C の行を指し示します。コンパイラが受け付けるものはすべて `docs/C.md` に載っています。

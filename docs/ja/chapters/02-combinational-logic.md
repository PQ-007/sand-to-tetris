第 1 章では、どの配線も 1 ビットを運び、トランジスタから作りました。ここからは自分で作ったゲートで作ります。まず AND、OR、XOR、それから信号を**選ぶ**回路、配線の束で**数**全体を運ぶ回路、そしてそれを**足す**回路です。この章の回路はすべて**組み合わせ回路**です。出力は今の入力だけで決まり、記憶はありません。記憶は第 3 章で登場します。

## ゲートで作る

NAND が真理値表のすべての行に合格したとき、あなたは役に立つことを証明しました。中で何が起きていようと、NAND は表のとおりに振る舞う、ということです。これ以降、シミュレータはレイヤー 1 のゲートの一つ一つを、四つのトランジスタをシミュレートする代わりに、その表で答えを引く一つのブロックとして扱います。これが **[[抽象化|abstraction]]** です。ものを**どうやるか**ではなく、**何をするか**で使うことです。それでも、ゲートをダブルクリックすれば中をのぞいて、自分のトランジスタが働くところを見られます。

シミュレータは時間も数えます。どのゲートも、入力が変わってから出力を更新するまでに 1 ステップ、つまり **[[ゲート遅延|gate-delay]]** 一つ分かかります。エディタは、回路が落ち着くまでに何ステップかかるかを表示します。この数字に注目しておきましょう。あなたのコンピュータがどれだけ速く動けるかを決めるものです。

## AND、OR、XOR

- **AND** は、NAND のあとに NOT を置いたものです。
- **OR** は、両方の入力が 0 のとき以外は 1 です。両方の入力を反転して NAND に入れましょう。NAND が 0 を出すのは反転した入力が両方 1 のときだけで、それはもとの入力が両方 0 のときだけです。
- **XOR**(「排他的論理和」)は、入力が**異なる**ときに 1 です。「a OR b、ただし両方ではない(NOT both)」です。

## 選ぶ:マルチプレクサ

**[[マルチプレクサ|multiplexer]]**(MUX)はデータのためのスイッチです。データ入力 a と b、そして**選択**入力 sel があります。sel が 0 なら出力は a を写し、sel が 1 なら b を写します。「sel が 0 のときだけ a を通し、sel が 1 のときだけ b を通し、二つを合わせる」という規則から作ります。

**[[デマルチプレクサ|demultiplexer]]**(DMUX)はその逆です。一つの入力を、sel に応じて出力 a か出力 b に送ります。

あなたの CPU はこれでいっぱいになります。マルチプレクサは、どのレジスタを読むか、次の命令を次のアドレスから取るかジャンプ先から取るかを選びます。

**[MUX を作る →](#/play/mux)** · **[DMUX →](#/play/dmux)**

## バスで運ぶ数

数を運ぶには、その[[2 進数|binary]]表現の[[ビット|bit]]一つにつき一本、何本かの配線が必要です。13 は 2 進数で `1101`(8 + 4 + 0 + 1)なので、4 本の配線が要ります。一つの数を運ぶ配線の束が **[[バス|bus]]** です。エディタでは、バスはその数を書いた一本の太い線です。あなたが作るコンピュータは 16 ビットのバスを使います。0 から 65,535 までの数を表せます。

<line-figure name="patch"></line-figure>

バスを扱う道具は二つあります。

- **[[スプリッタとジョイナ|splitter-and-joiner]]**:スプリッタはバスを 1 ビットずつの配線に分け、ビット 0(1 の位)から順に番号をつけます。ジョイナは 1 ビットずつの配線をまとめてバスに戻します。
- **繰り返し ×N**:部品を選んで**繰り返し**を 16 にすると、横に並んだ 16 個の複製になります。複製 *i* は、各バス入力のビット *i* を読み、各バス出力のビット *i* を出します。16 ビットの NOT は、NOT 一つを 16 回繰り返したものです。どの複製にも同じ信号が必要なら(16 ビットのマルチプレクサの選択ビット一つなど)、その入力の**共有**にチェックを入れます。

16 ビットの回路は、すべての入力でテストすることはできません。16 ビットの入力が二つあると、組み合わせは 40 億を超えます。そこでこうしたレベルでは、選んだ数行をチェックしたあと、組み込みの参照モデルと比べながら 2,000 個のランダムな入力を試し、いくつ失敗したかを知らせます。

## 足し算

2 進数の足し算は、筆算と同じように桁ごとに進みます。ただし、どの数字も 0 か 1 です。1 + 1 = 2 は 2 進数で `10` なので、0 を書いて 1 を繰り上げます。

- **[[半加算器|half-adder]]** は 2 ビットを足します。出力は二つ、**和**(1 の位)と **[[キャリー|carry]]**(2 の位)です。それぞれの真理値表を XOR と AND の真理値表と比べてみましょう。
- **[[全加算器|full-adder]]** は 3 ビットを足します。二つの桁と、右隣の桁から入ってくるキャリーです。筆算の 1 桁分そのものです。半加算器二つと OR 一つで作れます。
- **ADD16** は全加算器を 16 個つなぎ、各桁のキャリーを次の桁に渡します。最初の桁には、**Constant 0** から 0 のキャリーが入ります。

**[半加算器 →](#/play/halfadder)** · **[全加算器 →](#/play/fulladder)** · **[ADD16 →](#/play/add16)** · **[INC16 →](#/play/inc16)**

## この加算器はなぜ遅いのか

このように鎖として作った加算器が **[[リップルキャリー加算器|ripple-carry-adder]]** です。弱点は鎖そのものです。一番上の桁は、自分のキャリーがわかるまで終われません。そのキャリーは下の桁を待ち、その桁はさらに下の桁を待ち、という具合です。試してみましょう。

<ripple-adder></ripple-adder>

二つのことが目立ちます。

1. **最悪の場合は遅い。** 255 + 1 では、キャリーが最初の桁で生まれ、ほかのすべての桁を通り抜けなければなりません。
2. **「キャリーなし」でも波のように伝わる必要がある。** 255 + 0 ではキャリーは一度も起きませんが、それでも加算器は 8 ステップ全部かかります。各桁は、前の桁を待たなければ、キャリーがないことを**知る**ことができないからです。

シミュレータはあなたの ADD16 でも同じことを示します。2 + 1 は十数ゲート遅延ほどで落ち着きますが、0xffff + 1 は 64 かかります。16 ビットの AND はたった 2 です。回路の速さは、いちばん遅い経路で決まります。もっと速い加算器もあります。**キャリールックアヘッド**加算器は、ゲートを多く使って時間を稼ぎ、多くのキャリーを一度に求めます。このコースでは、リップルキャリーで十分です。

## 負の数

ADD16 は一番上の桁から出たキャリーを捨てるので、0xffff + 1 = 0 になります。これはバグではありません。負の数への鍵です。0xffff に 1 を足して 0 になるなら、0xffff はまさに −1 のように振る舞います。

これが **[[2 の補数|twos-complement]]** で、ほとんどのコンピュータが負の数を表す方法です。x の符号を反転するには、すべてのビットを反転して 1 を足します。16 ビットでは、0x8000 から 0xffff までのパターンが −32,768 から −1 を表し、一番上のビットが符号を示します。同じ加算器が、何も変えずに正の数も負の数も扱い、**a − b** は **a + NOT b + 1** になります。ALU を設計するとき、まさにこれを使います。

<details class="deeper">
<summary>さらに詳しく:「反転して 1 を足す」がうまくいく理由</summary>

16 ビットの数 x では、どの桁でも 1 と 0 を足すので、x + NOT x = 0xffff です。ですから x + NOT x + 1 = 0x10000 となり、17 番目のビットが捨てられて 0 が残ります。x に足して 0 になる数はまさに −x なので、NOT x + 1 = −x です。

</details>

## ALU

この章のすべてが **[[ALU|alu]]**(算術論理演算装置)で一つにまとまります。CPU の中で計算をする部分です。その演算があなたのコンピュータに何が計算できるかを決めるので、一緒に設計しました。16 ビットの数 a と b、そしていくつかの制御入力を受け取ります。

1. **invb** は、まず b のすべてのビットを反転します。1 との XOR はビットを反転し、0 との XOR はそのままにするので、これは invb を共有した XOR の 16 回の繰り返しです。
2. **f**(2 ビット)が結果を選びます。0 = ADD、1 = AND、2 = OR、3 = XOR です。加算器はキャリー入力 **cin** も受け取ります。
3. 三つの **[[フラグ|flags]]** が結果を表します。**z**(ゼロである)、**n**(負である:一番上のビットが 1)、**c**(加算器が一番上の桁からキャリーを出した。AND、OR、XOR では常に 0)です。

これだけの制御で、多くのことができます。

| 欲しいもの | f | invb | cin | 理由 |
|---|---|---|---|---|
| a + b | ADD | 0 | 0 | ふつうの足し算 |
| a − b | ADD | 1 | 1 | a + NOT b + 1、2 の補数 |
| a + 1 | ADD | 0 | 1 | b = 0 で |
| a − 1 | ADD | 1 | 0 | b = 0 で:0xffff、つまり −1 を足す |
| a AND NOT b | AND | 1 | – | b で立っているビットを消す |
| NOT a | XOR | 1 | – | b = 0 で:すべて 1 との XOR |

フラグは、プログラムが判断するための手段です。a から b を引いて z を見ます。1 なら a と b は等しかったのです。c を見ます。a − b のあと、c が 1 になるのは a ≥ b のときちょうどです(符号なしの数の場合)。第 4 章では、CPU がこれらのフラグを使ってジャンプするかどうかを選びます。

まず二つの補助部品が必要です。**XOR16** と、キャリーの鎖の両端を外に出す 16 ビット加算器です。ALU はここまでで最大の回路です。自分のゲートで作ると約 1,000 ゲート、深さは 80 ゲート遅延を超えます。高速モデル(下記)を試すのによい機会です。

## 高速モデル:作ったものを信頼する

あなたの ADD16 は 305 ゲートです。CPU には加算器がいくつも、ほかの部品もずっとたくさん入ります。そのすべてのゲートをシミュレートすると、積み重なって重くなります。そこで、部品が合格したら、それを **[[高速モデル|fast-model]]** に切り替えられます。同じ答えを 1 ステップで計算する組み込みの版です。

切り替えは決して自動ではありません。レベルマップでは、合格した部品それぞれに**実行方法**のボタンがあります。入れ替える前に、シミュレータはあなたの設計と高速モデルを比べます。入力ビットが 16 以下ならありうるすべての入力で(NOT16 なら 65,536 通り)、そうでなければ 10,000 個のランダムな入力でです。調べたどこかで食い違えば入れ替えは拒否され、例が示されます。そして、あとで部品を編集すると、もう一度チェックするまで、あなたの設計で動く状態に戻ります。

## 作ったもの、学んだこと

**作ったもの:** NAND と NOT から AND、OR、XOR。マルチプレクサとデマルチプレクサ。16 ビットの NOT、AND、OR、MUX。8 入力の OR。4 入力の 16 ビットマルチプレクサ。半加算器、全加算器、16 ビット加算器、インクリメンタ。そして、ゼロ、負、キャリーのフラグをもつ ALU。

**学んだこと:**

- 部品が正しいと証明されたら、何をするかだけで使える。それが抽象化である。
- マルチプレクサは信号を選び、デマルチプレクサは一つの信号をいくつかの行き先の一つへ送る。
- バスは 2 進数で数を運ぶ配線の束で、繰り返しは一つの部品をすべてのビットに適用する。
- 全加算器は筆算の 1 桁分で、それをつなぐとリップルキャリー加算器になる。
- 回路の速さはいちばん長い経路で決まり、リップルキャリー加算器のキャリーはすべての桁を渡らなければならないことがある。
- 2 の補数なら、同じ加算器で負の数を扱え、引き算は a + NOT b + 1 になる。
- 高速モデルは、一致チェックで両者が一致すると示されたあとでだけ、あなたの設計の代わりになれる。

- ALU は少数の制御入力で計算し、そのフラグ(ゼロ、負、キャリー)によってプログラムは数を比べられる。

**次へ:** 第 3 章では、回路に記憶を与えます。ラッチ、フリップフロップ、レジスタ、RAM です。

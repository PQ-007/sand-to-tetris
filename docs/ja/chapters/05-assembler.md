第 4 章では、プログラムは `0x4405, 0x0ca0, 0xcbfe` のような数の並びでした。CPU はそれで満足ですが、ほかの誰も満足しません。人はその代わりに、命令、レジスタ、プログラム中の場所に名前をつけた **[[アセンブリ言語|assembly-language]]** で書き、**[[アセンブラ|assembler]]** と呼ばれるプログラムがそれを **[[機械語|machine-code]]** に翻訳します。この章では、コンピュータのプログラムを書くための言語を学び、それからアセンブラを自分で書きます。

## 名前から数へ

アセンブラは魔法ではなく、自分がアセンブルする相手の CPU の上で動くわけでもありません。テキストを読んで数を書く、ふつうのプログラムです。1 行について、テキストを断片に分け、どの命令かを調べ、各部分を `docs/ISA.md` のビットフィールドに詰め込みます。ビット 15〜13 にグループ番号、次にレジスタ、次に定数かオフセットです。試してみましょう。

16 ビットのワードはどれも何かの命令なので、逆アセンブラ(逆向きの翻訳器)はいつでもワードを読み戻せます。アセンブラと逆アセンブラは 65,536 個すべてのワードで一致します。それが参照のアセンブラのテストの一つです。

## 言語

1 行は最大三つの部分からなり、どれも省略できます。**[[ラベル|label]]**、命令、そして `;` のあとのコメントです。

```
loop:   ADD  r0, r0, r1    ; total = total + counter
```

- ラベルと定数の**名前**は、英字、数字、`_` で書き、大文字と小文字は区別されます。命令名とレジスタ(`r0`〜`r7`)は大文字でも小文字でも書けます。
- **数**は 10 進数(`42`、`-5`)、16 進数(`0x4000`)、2 進数(`0b1111_0000`、桁の間に好きなように `_` を入れられます)、または文字(`'A'` は 65)で書けます。
- **メモリ**は `[r1 + 2]`、オフセットが 0 なら `[r1]` と書きます。
- **ジャンプ**はラベルを名指しし、どれだけ離れているかはアセンブラが計算します。数を書くとそれが距離そのものになります。`JMP 0` は自分自身へジャンプします。

### 近道とディレクティブ

**[[疑似命令|pseudo-instruction]]** は、アセンブラは理解しても CPU にはない名前です。1 個以上の本物の命令になります。

| 書くもの | アセンブラが作るもの |
|---|---|
| `SET16 r1, 0x4000` | `SET r1, 0` と `SETH r1, 0x40`(0 から 255 の値なら `SET` だけ) |
| `INC r1` · `DEC r1` | `ADDI r1, 1` · `SUBI r1, 1` |
| `HALT` | `JMP 0`:自分自身へ永遠にジャンプする |
| `NOP` | `JMP 1`:次の命令へ。何も変えない |

**[[ディレクティブ|directive]]** はドットで始まり、命令になる代わりにアセンブラに話しかけます。`.equ SCREEN 0x4000` は数に名前をつけます。`.data` はデータセクションに切り替え、そこでは `.word 1, 2, 3` が数を、`.space 8` が 0 を 8 個置きます。`.code` でもとに戻ります。私たちのコンピュータはプログラムを LOAD で読めない ROM に置くので、データは RAM に入ります。プログラムが始まる前に、**[[ローダ|loader]]** がデータセクションを RAM のアドレス 0 からコピーし、データのラベルはその RAM のアドレスになります。

```
.data
shapes: .word 0x0F00, 0x4444     ; RAM[0] と RAM[1]
.code
        SET16 r1, shapes         ; r1 = 0
        LOAD  r2, [r1 + 1]       ; r2 = 0x4444
```

## アセンブラの仕組み

参照のアセンブラもあなたのアセンブラも、同じく四つの段階で作られています。どの段階も、前の段階が作ったものを受け取ります。

### 1. 字句解析

1 行をトークンに切り分けます。`loop:` はラベル、`ADD` と `r1` は名前、`0x10` は数、`,` `[` `]` `+` は区切り記号です。空白とコメントは消えます。ここで、おかしな文字や `12ab` のような数に気づきます。

### 2. 構文解析

トークンを 1 行として読みます。省略できるラベル、次に命令かディレクティブ、次にコンマで区切ったオペランドです。`r0`〜`r7` はレジスタになり、ほかの名前はあとのために名前のまま残ります。ここで、コンマや `]` の抜けに気づきます。

### 3. 配置:1 回目のパス

ここが難問です。`JNZ loop` では、アセンブラは `loop` がどこにあるかを知らなければなりませんが、前方へのジャンプは、もっと下でしか出てこないラベルを名指しすることがあります。そこでアセンブラはプログラム全体を 2 回読みます。1 回目のパスで、すべての行にアドレスを与え、すべての名前を **[[シンボルテーブル|symbol-table]]** に集めます。どの命令も 1 ワードですが、SET16 だけは値によって大きさが変わるので、それも 1 回目のパスで決めます。このように動くアセンブラが **[[2 パスアセンブラ|two-pass-assembler]]** です。

### 4. 符号化:2 回目のパス

これですべての名前に値があるので、各行をワードに変えられます。ラベルを引き、ジャンプの距離を計算し、どの数もそのフィールドに収まるか確かめ、ビットを詰め込みます。

良いアセンブラは最初の間違いで止まりません。問題のある行をすべて報告し、何がおかしいかを述べ、その行を指し示します。

## アセンブラの由来

プログラムを数で書く時代は、ほんの数年しか続きませんでした。1947 年、キャスリーン・ブースは、バークベックの ARC2 コンピュータのために、命令を 2 進数ではなく短い記号で書く「短縮記法(contracted notation)」を説明しました。これはよく最初のアセンブリ言語と呼ばれますが、その呼び名はあとから付いたもので、議論があります[@booth-contracted-notation]。1949 年 5 月、デイビッド・ウィーラーは、ケンブリッジの EDSAC のための「初期命令(initial orders)」を書きました。英字の略号で紙テープに穿孔されたプログラムを読み、メモリに置く数十ワードです。これはよく最初のアセンブラと呼ばれます。これもまた「最初」をめぐる議論のある主張です。その年の 9 月の第 2 版は、読み込みながらアドレスの調整も行いました[@edsac-initial-orders]。それ以来、どのアセンブラも同じ仕事をしています。名前を受け取り、数を出すのです。

## プログラムを動かす

**マシン**のページでは、プログラムを書き、アセンブルし、実行できます。あなたが設計したコンピュータの画面、キーボード、レジスタ、RAM の上でです。最初は組み込みのアセンブラを使います。あなた自身のアセンブラがワークショップのテストにすべて合格したら、代わりにそれを選べます。するとプログラムは、ビットに至るまで、あなたの書いたコードを通って動きます。プログラムは CPU の高速モデルの上で動くので、ゲームにも十分な速さです。

## 作ったもの、学んだこと

**作ったもの:** それぞれにテストのある四つの段階からなるアセンブラ。私たちのアセンブリ言語を、機械語とデータイメージに変えます。そして、コンピュータの画面とキーボードの上で動くプログラム。

**学んだこと:**

- アセンブリ言語は、命令、レジスタ、アドレスに名前を与える。アセンブラはそれを機械語に翻訳するふつうのプログラムである。
- 疑似命令とディレクティブは、CPU を変えずにプログラムを短く書けるようにする。
- ラベルは定義より前に使えるので、アセンブラは 2 回のパスを行う。1 回目でシンボルテーブルを作り、2 回目で符号化する。
- プログラムが必要とするデータは専用のセクションに置かれ、プログラムが始まる前にローダがそれを RAM にコピーする。

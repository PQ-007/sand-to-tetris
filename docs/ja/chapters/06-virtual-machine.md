アセンブリは数に比べれば大きな進歩ですが、まだ CPU のように考えなければなりません。8 個のレジスタのどれに何が入っているか、サブルーチンがどれを変えてよいか、残りを RAM のどこに保存するか。本物の言語のコンパイラ(次の章)は、それを全部一度に正しくこなさなければならなくなります。そこで仕事を二つに分けます。コンパイラは **[[仮想マシン|virtual-machine]]** のためのコードを書きます。定義としてだけ存在する機械で、レジスタを気にせずにコンパイルできるほど単純なものです。そして、別の、ずっと小さなプログラムである**トランスレータ**が、そのコマンドの一つ一つを数行のアセンブリに変えます。この章では VM を学び、そのトランスレータを書きます。

## スタック一つでできた機械

私たちの VM は **[[スタックマシン|stack-machine]]** です。名前で呼べるレジスタはありません。その代わり、どのコマンドも入力を **[[スタック|stack]]** の一番上から取ります。皿を積むのと同じで、一番上に皿を載せる(**プッシュ**)か、一番上の皿を取る(**ポップ**)ことしかできません。`add` は数を二つポップし、その和をプッシュします。

これで、式はその数と演算子を順に並べたものになります。(3 + 4) × 2 を計算するには:

```
push 3      ; スタック: 3
push 4      ; スタック: 3 4
add         ; スタック: 7
push 2      ; スタック: 7 2
mul         ; スタック: 14
```

決めることは何もありません。「どのレジスタが空いているか」もありません。まさにそれが、コンパイラがこの種の機械を好む理由です。ステップ実行してみて、それから関数呼び出しも見てみましょう。

VM の全体は `docs/VM.md` にあります。主な選択は一緒に決めました。次のとおりです。

| 問い | 選んだもの | 理由 |
|---|---|---|
| どんな VM か | スタックマシン | 式が順番どおりにコンパイルでき、各コマンドを単独で翻訳できる |
| 値の置き場所 | 番号付きの `local`、`arg`、`global` 変数と、`load` と `store` | 考え方が少ない。配列、ポインタ、画面、キーボードはどれもただのアドレス |
| 「真」とは何か | −1(16 ビットすべて 1)、偽は 0 | すると `and`、`or`、`not` がビットにも条件にも使える |
| 掛け算 | `mul`、`div`、`mod` はコマンド | CPU は掛け算できないので、トランスレータが小さなルーチンを加える |

## 変数とメモリ

`push local 2` は今の関数のローカル変数 2 の値をプッシュし、`set local 2` は一番上をポップしてそこに入れます。`arg` は関数の引数について、`global` はすべての関数が共有する変数について、同じように働きます。それ以外はすべてメモリです。`load` はアドレスをポップしてそこに蓄えられたワードをプッシュし、`store` は値をアドレスに書きます。画面とキーボードはアドレスなので(第 4 章)、同じ二つのコマンドでピクセルを描き、キーを読めます。

```
push 0x4000     ; 画面の最初のワード
push -1         ; 点灯したピクセル 16 個
store
```

## 判断:真は −1

`lt`、`eq` などの比較は、真なら −1、偽なら 0 をプッシュします。16 ビットすべてが立っているので、`not` は真を偽に、偽を真に変え、`and` と `or` は条件を組み合わせます。一組のビット演算のコマンドで両方の仕事ができるのです。`jumpif L` は値をポップし、それが 0 でなければ `label L` へジャンプします。`jumpifnot` は 0 ならジャンプします。ループにも if-then-else にも、これだけあれば十分です。

## 関数とフレーム

`call f 2` は、一番上の二つの値を引数として関数 `f` を実行します。`f` が `return` で終わると、引数は二つとも消え、その場所に結果が置かれます。呼び出し側から見れば、呼び出しは `add` と同じく、いくつかの値を一つに変えるコマンドにすぎません。

それがうまくいくのは、どの呼び出しも同じスタックの上に自分の **[[スタックフレーム|stack-frame]]** をもつからです。`f` が始まると、あとのために二つのもの、戻り先と呼び出し元のフレームを保存し、ローカル変数のための場所を空けます。レジスタ **FP** がフレームを指すので、`local 0` は常に FP + 0 にあり、引数は保存したワードのすぐ上にあります。もう一つのレジスタ、**[[スタックポインタ|stack-pointer]]**(SP)は、常にスタックの一番上を指します。`f` が戻るときは、最初の引数があった場所に結果を置き、SP と FP をもとに戻し、戻りアドレスへジャンプします。

呼び出しごとに自分のフレームがあるので、関数は自分自身を呼べます。それが **[[再帰|recursion]]** です。デモの階乗では、`fact(3)` が `fact(2)` を呼び、それが `fact(1)` を呼びます。同じ関数のフレームが三つ、それぞれ自分の `arg 0` をもって、上へ積み重なります。フレームのどこに何を置くか、どのレジスタが何を意味するかを厳密に決めたものが、`docs/VM.md` の **[[呼び出し規約|calling-convention]]** です。翻訳のどの部分もそれに従います。だからこそ、あなたが翻訳したコマンドが、組み込みのトランスレータが翻訳した別のコマンドと並んで動けるのです。

## スタックからレジスタへ

トランスレータは一度に一つのコマンドを扱います。ほとんどのコマンドは 3〜8 個の命令になります。たとえば `add` は:

```
LOAD  r1, [r6]        ; b = 一番上(r6 が SP)
ADDI  r6, 1           ; それをポップ
LOAD  r0, [r6]        ; a = 新しい一番上
ADD   r0, r0, r1
STORE r0, [r6]        ; 和が a と入れ替わる
```

`mul`、`div`、`mod` は、トランスレータがプログラムに加える二つのルーチンを呼びます。2 進数の掛け算は 0 と 1 だけの筆算です。一方の数の 1 のビットごとに、もう一方の数を位置をずらして足します。割り算は筆算の割り算です。1 ビットずつ下ろし、引けるところで引きます。

代償に気づいたかもしれません。手で書いたアセンブリならレジスタに置いておく値が、どれも RAM へ行って戻ってきます。実際のシステムは、**レジスタ割り付け**のような、コンパイラでのもっと多くの仕事でその差を埋めます。私たちのものは単純なままにしますが、どのみち CPU の高速モデルはゲームに十分な速さです。

VM には、直接実行できる定義もあります。デモで使っている **[[インタプリタ|interpreter]]** で、翻訳する代わりに 1 ステップに 1 コマンドを実行します。参照のトランスレータのテストは、何百ものランダムなプログラムを両方のやり方で走らせ、結果が一致するか確かめています。

## 仮想マシンの由来

スタックマシンは、もともと本物のハードウェアでした。1961 年に発表され、アセンブリではなく ALGOL で書いたプログラムのために設計された Burroughs B5000 は、すべての算術をスタックの上で行ったので、命令がレジスタや一時的な場所を名指しする必要がまったくありませんでした[@burroughs-b5000]。その 10 年後、チューリッヒ工科大学のニクラウス・ヴィルトのグループの Pascal コンパイラは、Pascal-P として広まりました。仮想スタックマシンのための p コードを出力するコンパイラと、そのインタプリタです。Pascal を新しいコンピュータに移すには、そのインタプリタだけを書けばよかったのです。1977 年に公開された UCSD Pascal は、この考えの上に移植可能なシステム全体を築きました[@pascal-p-code]。Java 仮想マシンも同じやり方でプログラムを動かします。メソッドの呼び出しごとに、ローカル変数とオペランドスタックをもつフレームが与えられ、`iadd` のような命令はオペランドをポップして結果をプッシュします[@jvm-operand-stack]。2019 年 12 月に W3C 勧告となり、主要なブラウザすべてで動く WebAssembly も、その計算モデルをスタックマシンとして記述しています[@webassembly-stack]。

## 作ったもの、学んだこと

**作ったもの:** スタックマシンのコマンドをアセンブリに変える VM トランスレータ。関数、再帰、掛け算と割り算のルーチンを備えています。そして、コンピュータの画面とキーボードの上で動く VM プログラム。

**学んだこと:**

- 仮想マシンは、ハードウェアではなく文書で定義された機械である。トランスレータやインタプリタが、それを特定の CPU の上で実現する。
- スタックマシンはオペランドをスタックの一番上から取り、結果をプッシュするので、式はその値と演算子を順に並べたものにコンパイルされる。
- 関数呼び出しのたびにスタックフレーム(戻りアドレス、呼び出し元のフレームポインタ、ローカル変数)が作られるので、関数は互いに、また自分自身を呼べる。
- 呼び出し規約が何をどこに置くかを決めるので、別々に翻訳した部分がともに動く。

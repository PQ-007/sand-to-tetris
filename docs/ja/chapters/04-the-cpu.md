これで、コンピュータに必要な部品はすべてそろいました。計算する ALU、記憶するレジスタと RAM、自分がどこにいるかを知っているプログラムカウンタです。足りないのは、それらを協力させるもの、**[[プロセッサ|processor]]**、つまり CPU です。CPU は一つの仕事を何度も繰り返します。実際の機械では 1 秒に何十億回もです。次の命令を読み、その意味を解き、実行する。このループが **[[フェッチ・デコード・実行サイクル|instruction-cycle]]** です。この章ではそれを作ります。

## 命令は数である

プログラムは **[[命令|instruction]]** の並びで、命令はただの数です。私たちのコンピュータでは、命令はそれぞれ 16 ビットのワードです。いくつかのビットが**何を**するか(足す、ストアする、ジャンプする)を表し、ほかのビットが**何で**するか(どのレジスタか、どの定数か)を表します。ただのワードとして蓄えられたプログラムが **[[機械語|machine-code]]** です。人はその代わりに **[[アセンブリ言語|assembly-language]]** で、1 命令につき短い 1 行で書きます。

<line-figure name="riffle"></line-figure>

```
        SET  r0, 0        ; sum = 0
        SET  r1, 10       ; i = 10
loop:   ADD  r0, r0, r1   ; sum = sum + i
        SUBI r1, 1        ; i = i - 1
        JNZ  loop         ; i が 0 でなければもう一度
done:   JMP  done         ; 停止:r0 = 55
```

命令の完全な一覧と、それぞれがビットでどう書かれ、何をするかの厳密な定めが **[[命令セット|instruction-set]]** です。これは契約です。ハードウェアは書かれたとおりに動くことを約束し、ここからテトリスまでのすべてのプログラムがこれで書かれます。だから私たちは、一つずつ決めながら一緒に設計しました。全文は `docs/ISA.md` にあります。

## 決めたこと

| 問い | 選んだもの | 理由 |
|---|---|---|
| レジスタ | r0 から r7 までの汎用レジスタ 8 個 | メモリとの行き来を繰り返さずに、ゲームの作業用の値を置ける |
| メモリ | 別のプログラム ROM | 次の命令のフェッチとデータの読み出しを同時にできる |
| 命令の大きさ | どの命令も 16 ビットのワード一つ | フェッチが単純。16 ビットの定数には 2 命令(SET、次に SETH)が必要 |
| 判断 | ジャンプは保存されたフラグ Z、N、C を調べる | ALU がすでに作っているフラグを使う |
| 呼び出し | CALL は戻りアドレスを r7 に保存する | 1 クロックサイクルで、余分なハードウェアがほとんど要らない |
| シフト | バレルシフタで 0〜15 桁を一度に | ゲームではビットパターンを横にずらすことがしょっちゅうある |
| 装置 | メモリマップドの画面とキーボード | 描くのはストアするだけ。特別な命令は要らない |

プログラムをデータから切り離しておく方式は、よく **[[ハーバード・アーキテクチャ|harvard-architecture]]** と呼ばれます。数を別のカウンタに置いたまま、命令を穿孔紙テープから読んだハーバード Mark I にちなむ名前ですが、名前の本当の由来には議論があります[@harvard-architecture]。これは、プログラムとデータが一つのメモリを共有する、第 0 章の **[[プログラム内蔵方式|stored-program]]** の設計とは反対です[@von-neumann-edvac]。この分離は今もよく使われています。マイクロチップ社の AVR マイクロコントローラは、今の命令を実行しながら次の命令をフェッチするので、ほとんどの命令が 1 クロックサイクルで済みます[@avr-harvard]。

多くのレジスタ、同じ大きさの単純な命令、そして LOAD と STORE だけがメモリに触れること。これらを合わせたものが **[[RISC|risc]]** の流儀です。1975 年ごろからのジョン・コックの IBM 801 プロジェクトから育ち、1980 年のデイビッド・パターソンとデイビッド・ディッツェルの論文で提唱されました[@risc]。戻りアドレスをレジスタに保存するのは ARM プロセッサも同じです。その「リンク付き分岐」は戻りアドレスを r14、つまり **[[リンクレジスタ|link-register]]** に置きます[@arm-link-register]。

## 命令の形式

どの命令も 3 ビットのグループ番号(ビット 15〜13)で始まります。残りはグループによって違います。

| グループ | ビット 15〜13 | 続き | 例 |
|---|---|---|---|
| ALU | 000 | rd、ra、rb と、ALU の f、invb、cin | `ADD r3, r1, r2` |
| CMP | 001 | ra、rb、ALU の制御(フラグだけが残る) | `CMP r1, r2` |
| IMM | 010 | rd、2 ビットの種類、8 ビットの数 | `SET r1, 5`、`SUBI r1, 1` |
| SHIFT | 011 | rd、ra、向き、桁数 | `SHR r3, r3, 4` |
| LOAD | 100 | rd、ra、7 ビットのオフセット | `LOAD r6, [r0 + 2]` |
| STORE | 101 | rs、ra、7 ビットのオフセット | `STORE r3, [r0 + 2]` |
| JUMP | 110 | 3 ビットの条件、10 ビットのオフセット | `JNZ loop` |
| CALL / JR | 111 | オフセット、またはジャンプ先のレジスタ | `CALL draw`、`RET` |

ALU のグループを見てください。下位 4 ビットが ALU の f、invb、cin のピンに**そのまま**行きます。偶然ではありません。ALU と命令セットを、互いに合うように設計したのです。16 ビットのワードはどれも何かの命令を意味するので、CPU に実行できないものが渡されることは決してありません。

## 制御ユニット

**[[制御ユニット|control-unit]]** は、命令と保存されたフラグを読み、CPU の残りを操るすべての信号を決めます。どのレジスタを読むか(ra、rb)、どれに書くか(wa)、そもそも書くかどうか(we)、ALU が何をするか、その 2 番目の入力がレジスタか命令中の定数か、何を書くか(ALU の結果、シフタの結果、定数、メモリからのワード、または戻りアドレス)、そして PC がジャンプするかどうかです。

これはふつうの組み合わせ回路で、すでにもっているゲートで作れます。いちばん便利な手は、入力を 1 につなぎ、sel にグループ番号を入れた DMUX8WAY です。命令のグループごとに一本の配線が得られ、その命令のグループの配線だけが 1 になります。あとはほとんどの信号が、それらの配線と命令のビットを AND と OR でいくつか組み合わせたものになります。

## データパス

CPU の残りは **[[データパス|datapath]]** です。データを保持し、動かす部品です。

- **[[レジスタファイル|register-file]]** は r0 から r7 を保持します。二つのレジスタを同時に読み(`ADD r3, r1, r2` では ALU に r1 と r2 が一緒に必要です)、クロックエッジで一つに書き込みます。Register 八つ、DMUX8WAY 一つ、MUX8WAY16 二つでできています。
- **[[バレルシフタ|barrel-shifter]]** は、ワードを 0 から 15 までの任意の桁数だけ 1 ステップでずらします。1、2、4、8 だけずらす四つの段があり、それぞれオンかオフです。5 ずらすなら 1 段目と 3 段目です。各段は MUX16 一つで、ずらすこと自体は配線だけで済みます。
- ALU、その 2 番目の入力を選ぶ MUX16、書き込む結果を選ぶ MUX8WAY16、フラグ用の Bit 三つ、ジャンプ先(PC + オフセット)を求める加算器、そしてプログラムカウンタ。

**[レジスタファイルを作る →](#/play/regfile)** · **[バレルシフタを作る →](#/play/shifter)** · **[CPU を作る →](#/play/cpu)**

<summary>さらに詳しく:どれくらい速く動けるか</summary>

すべて自分のゲートで作ると、参照の CPU は約 4,300 ゲートで、その中のいちばん遅い経路は 110 ゲート遅延です。命令のビットが、制御ユニット、レジスタファイル、ALU のリップルキャリー加算器、結果のマルチプレクサを通ってから落ち着きます。どの命令にも 1 クロックサイクルが割り当てられるので、ずっと早く終わる命令があっても、クロックはこのいちばん遅い経路が許すより速くは刻めません。実際のプロセッサは、各命令を段階に分け、いくつもの命令を同時に処理すること(**パイプライン**)でこれを回避しますが、その代わり制御ユニットはずっと複雑になります。

</details>

## メモリとコンピュータ

CPU は四つのピンでメモリとやりとりします。addrM(ALU から来るアドレス)、outM(ストアする値)、writeM(今ストアする)、inM(読み戻したワード)です。そのピンの向こうには**メモリマップ**があり、各アドレスが何を意味するかを決めます。

<line-figure name="computer"></line-figure>

| アドレス | そこにあるもの |
|---|---|
| 0x0000–0x3FFF | RAM16K:16,384 ワード。RAM4K 四つで作る |
| 0x4000–0x42FF | 画面:128 × 96 ピクセル、各 1 ビット、1 ワードに 16 個 |
| 0x6000 | キーボード:押されているキーのコード |
| それ以外 | 読むと 0、書き込みは無視 |

画面では、行 y は 0x4000 + 8y から始まる 8 ワードで、ワードのいちばん左のピクセルはその最上位ビットです。2 進数で書いたワードは、その 16 個のピクセルそのままに見えます。これが **[[メモリマップド I/O|memory-mapped-io]]** です。画面に描くのはふつうの STORE、キーを読むのはふつうの LOAD です。プログラム ROM はコンピュータの外にあります。テストや、のちにはサイトが、本物の ROM チップと同じように、pc の位置の命令を CPU に渡します。

## CPU の高速モデル

テトリスには 1 秒間に何十万もの命令が必要で、すべてのゲートのシミュレーションでこなせる量をはるかに超えます。そこで CPU とメモリマップには、第 3 章の RAM と同じように高速モデルがあります。CPU が合格したら、10,000 回のランダムなクロックサイクルで高速モデルと比べられます。すべてのサイクルで一致すれば、レベルマップで切り替えられ、コンピュータは全速で動きます。チェックでは、メモリ部品にはすでに高速モデルを使っています。ゲートで作った RAM16K は何百万ゲートにもなるからです。

## 作ったもの、学んだこと

**作ったもの:** バレルシフタ、RAM16K、レジスタファイル、制御ユニット、CPU 全体、画面とキーボードをもつメモリマップ、そしてそれらをつなぐコンピュータ。一緒に設計した命令セットのすべての命令を、1 クロックサイクルに 1 つずつ実行します。

**学んだこと:**

- プログラムは命令の並びで、命令は数である。命令セットはハードウェアとソフトウェアの間の契約である。
- CPU はフェッチ、デコード、実行を繰り返す。制御ユニットが命令を制御信号に変え、データパス(レジスタ、ALU、シフタ)が仕事をする。
- 設計は、単純さと、速さや大きさを天秤にかける。別のプログラム ROM と 1 ワードの命令によって、どの命令も 1 サイクルで終わる。
- 条件付きジャンプは前の命令が保存したフラグを使い、CALL と RET はリンクレジスタを使う。
- メモリマップド I/O では、装置はただのアドレスである。画面はメモリで、描くことはストアすることである。

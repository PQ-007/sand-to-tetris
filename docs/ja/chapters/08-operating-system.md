あなたの C Shard のプログラムは、すでに `mem[0x4000 + ...]` に書き込むことで描画できます。けれども、どのプログラムもピクセルのアドレスとビットマスクを毎回自分で求めなければなりません。**[[オペレーティングシステム|operating-system]]** は、すべてのプログラムが共有するコードです。大きなシステムは、多くのプログラムを同時に動かし、ファイルも管理します。私たちのものはどちらもしません。画面、文字、キーボード、時間、乱数のための C Shard の関数のライブラリで、どのプログラムの前にも置かれます。あなたが設計した言語で、自分で書きます。

## 決めたこと

| 問い | 選んだもの | 理由 |
|---|---|---|
| 時間の計り方 | アドレス 0x6001 のフレームカウンタ、1 秒に 60 カウント | シミュレーションの速さに関係なく、ゲームが同じ速さで動く |
| 乱数 | OS の中にソフトウェアで書いた生成器 | 新しいハードウェアが要らず、「乱数」が本当はどう作られるかがわかる |
| キーボードのコード | ASCII に加えて Enter 13、Backspace 8、Escape 27、矢印 128〜131 | 1 バイトに収まり、どの例もすでに使っている |
| OS の使い方 | どの C Shard プログラムの前にも置かれる | 言語は変わらない。OS の名前がすでに使われているだけ |

タイマーは新しいハードウェアです。メモリマップは、0x6000 のキーボードの隣で、アドレス 0x6001 を `timer` 入力に送るようになりました。以前にメモリマップやコンピュータを作っていたら、それらのレベルをもう一度開いて、新しい入力を配線してください。関数の完全な一覧は `docs/OS.md` にあります。

## ピクセルはビットである

画面は 768 ワードで、1 行に 8 ワード、各ピクセルは 1 ビットです。ピクセル (x, y) を点灯するために、`plot` はそのワードを `0x4000 + 8y + x / 16` に見つけ、正しい位置にだけ 1 がある **[[ビットマスク|bit-mask]]** を作ります。`0x8000 >> (x % 16)` です。いちばん左のピクセルが最上位ビットだからです。マスクとの OR でピクセルがオンになり、その反転との AND でオフになります。ワードのほかのピクセルはそのまま残ります。

<line-figure name="phosphor"></line-figure>

塗りつぶした長方形は、すべてのピクセルについて `plot` を呼んでも描けますが、ゲームはたくさんのピクセルを描き直します。`fill_rect` はワード単位で働きます。各行で、次のワードの境目までのピクセルを、1 がいくつか並んだマスク一つで覆うので、1 ワード分が 16 回ではなく 1 回の読み出しと 1 回の書き込みで済みます。C Shard では、ワードの左から `bit` ピクセル目から始まる n 個の 1 は `(-1 << (16 - n)) >> bit` です。

## 数でできたフォント

文字を書くには、OS にはすべての文字の絵が必要です。私たちのものは、1 文字 3 × 5 ピクセルの **[[ビットマップフォント|bitmap-font]]** で、このプロジェクトのために描きました。15 ピクセルは 1 ワードに収まるので、空白から `_` までのフォント全体が 64 個の数です。文字は 4 × 6 ピクセルのセルに置かれ、文字の間と行の間にすき間が残るので、画面には 32 列 16 行の文字が入ります。

<font-demo></font-demo>

`draw_char` は文字のワードを引き、1 のビットごとにピクセルを置きます。`draw_text` は文字を横に並べて描き、`draw_int` は 10 で何度も割ることで数を桁に変えます。負の数でも動くので、16 ビットでは正の相方をもたない −32768 も正しく表示されます。

## キーと時間

`key()` は 0x6000 のキーボードのワードを読みます。`wait_key()` はキーが押されてから離されるまで待つので、どれだけ長く押していても 1 回の押下は 1 回と数えられます。`ticks()` は 0x6001 のフレームカウンタを読み、`wait(n)` はさらに n フレームが過ぎるまでループします。カウンタは CPU の外から来るので、落ちてくる Bitfall のピースは、遅い設定でも速い設定でも同じ速さで動きます。

## 数式から作る乱数

言われたとおりにしか動かないコンピュータは、サイコロを振れません。できるのは、ランダムに見える数列を計算することです。**[[疑似乱数|pseudo-random]]** です。私たちのものは xorshift 生成器を使います。数を、自分自身をずらした写しと組み合わせます。`s ^ (s << 7)`、次に `s ^ (s >> 9)`、次に `s ^ (s << 8)` です。この三つのシフトで、数列は 0 でない 16 ビットの値 65,535 個すべてを通ってから繰り返します。リポジトリのテストが、そのすべてのステップを確かめています。

同じ最初の値、つまり同じ **[[シード|random-seed]]** からは、いつも同じ数列が出ます。ゲームを毎回違うものにするために、OS は最初にキーが押されたとき、タイマーからシードを設定し直します。すると、プレイヤーが押すまでにどれだけ待ったかがゲームを決めます。そして、60 分の 1 秒単位で同じだけ待つことを、わざと 2 回できる人はいません。

## 由来

初期のコンピュータは一つの仕事をこなすと、オペレータが次の仕事を読み込むのを待っていました。1956 年、ゼネラルモーターズ研究所のロバート・パトリックとノースアメリカン・アビエーションのオーウェン・モックが、IBM 704 のために GM-NAA I/O を書きました。この機械のための最初のオペレーティングシステムとされ、主な仕事は、今のプログラムが終わったら次のプログラムを自動的に始めることでした[@gm-naa-io]。xorshift 生成器は、2003 年にジョージ・マルサリアが「単純で、きわめて速い」乱数生成器として発表しました[@marsaglia-xorshift]。私たちの OS が使う三つのシフトは、その仲間の小さな 16 ビット版です。

## 作ったもの、学んだこと

**作ったもの:** C Shard で書いたオペレーティングシステム。ピクセル、長方形、フォント、文字と数、キーボード、タイマー、乱数を備えています。そして、コンピュータのメモリマップの中のタイマー装置。

**学んだこと:**

- 描くことはビットを蓄えることである。アドレスがワードを見つけ、マスクがその中のピクセルを選ぶ。
- ワード単位で処理すると、ピクセル単位より最大 16 倍速い。
- フォントはデータである。各文字は数として蓄えた小さな絵である。
- 時間は CPU の外から来るので、プログラムはどんな機械でも同じ速さで動く。
- コンピュータの乱数は数式から生まれる。シードが数列を決める。

**次へ:** [プログラム](#/programs)。落ちものゲーム Bitfall を、あなたの OS の上の C Shard で。さらに、アセンブリへ直接コンパイルした C の 7 本のゲーム。すべて、トランジスタから作ったコンピュータの上で動きます。

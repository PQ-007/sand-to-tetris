Ассемблер тоонуудаас хамаагүй дээр ч та төв процессор шиг сэтгэсээр л байна: найман регистрийн аль нь юуг хадгалж байгаа, дэд програм алийг нь өөрчилж болох, үлдсэнийг RAM-ийн хаана хадгалах. Жинхэнэ хэлний хөрвүүлэгч (дараагийн бүлэг) энэ бүгдийг нэг дор зөв хийх ёстой болно. Тиймээс бид ажлыг хоёр хуваана. Хөрвүүлэгч **[[виртуал машин|virtual-machine]]**-д зориулж код бичнэ: зөвхөн тодорхойлолт хэлбэрээр оршдог, регистрийн талаар санаа зовохгүйгээр хөрвүүлэхэд хангалттай энгийн машин. Дараа нь тусдаа, хамаагүй жижиг програм болох **translator** түүний команд бүрийг хэдэн мөр ассемблер болгоно. Энэ бүлэгт та VM-ийг сурч, дараа нь тэр translator-ыг бичнэ.

## Ганц stack-аас бүтсэн машин

Манай VM бол **[[stack machine|stack-machine]]**. Түүнд нэрлэж болох регистр байхгүй. Үүний оронд команд бүр оролтоо **[[stack]]**-ийн оройгоос авна, яг таваг овоолох шиг: зөвхөн дээр нь таваг тавих (**push**) эсвэл оройн тавгийг авах (**pop**) боломжтой. `add` хоёр тоог pop хийж, нийлбэрийг нь push хийнэ.

Ингэснээр илэрхийлэл нь тоо ба үйлдлүүдийнхээ дараалсан жагсаалт болно. (3 + 4) × 2-ыг бодохын тулд:

```
push 3      ; stack: 3
push 4      ; stack: 3 4
add         ; stack: 7
push 2      ; stack: 7 2
mul         ; stack: 14
```

Шийдэх зүйл алга: "аль регистр сул байна?" гэх асуулт байхгүй. Хөрвүүлэгч ийм машинд дуртай шалтгаан нь яг энэ. Алхам алхмаар ажиллуулаад, дараа нь функцийн дуудлагаар туршаад үз:

VM бүхэлдээ `docs/VM.md`-д бий. Гол сонголтуудыг бид хамтдаа хийсэн:

| Асуулт | Бидний сонголт | Яагаад |
|---|---|---|
| Ямар VM | stack machine | илэрхийлэл дарааллаараа хөрвөнө, команд бүр тус тусдаа хөрвөнө |
| Утга хаана байх | дугаартай `local`, `arg`, `global` хувьсагч, мөн `load` ба `store` | цөөн санаа; массив, pointer, дэлгэц, гар бүгд зүгээр л хаяг |
| "Үнэн" гэж юу вэ | −1 (16 бит бүгд 1), худал нь 0 | `and`, `or`, `not` бит болон нөхцөлийн аль алинд ажиллана |
| Үржих | `mul`, `div`, `mod` бол команд | төв процессор үржиж чадахгүй тул translator тэдэнд жижиг дэд програм нэмнэ |

## Хувьсагч ба санах ой

`push local 2` нь одоогийн функцийн 2-р local хувьсагчийн утгыг push хийж, `set local 2` оройг түүн рүү pop хийнэ. `arg` функцийн аргументуудад, `global` бүх функцийн хуваалцдаг хувьсагчдад адилхан ажиллана. Бусад бүх зүйл санах ой: `load` хаягийг pop хийж, тэнд хадгалсан үгийг push хийнэ, `store` утгыг хаяг руу бичнэ. Дэлгэц ба гар бол хаяг (4-р бүлэг) учраас эдгээр хоёр команд пиксел зурж, товч уншина:

```
push 0x4000     ; дэлгэцийн эхний үг
push -1         ; асаалттай 16 пиксел
store
```

## Шийдвэр: үнэн бол −1

`lt`, `eq` болон бусад харьцуулалт үнэн бол −1, худал бол 0-ийг push хийнэ. 16 бит бүгд 1 байгаа тул `not` үнэнийг худал, худлыг үнэн болгож, `and` ба `or` нөхцлүүдийг нийлүүлдэг тул нэг багц бит команд хоёр ажлыг хийнэ. `jumpif L` утгыг pop хийж, 0 биш бол `label L` руу үсэрнэ; `jumpifnot` 0 бол үсэрнэ. Давталт эсвэл if-then-else-д хэрэгтэй бүх зүйл энэ.

## Функц ба frame

`call f 2` нь `f` функцийг оройн хоёр утгыг аргумент болгон ажиллуулна; `return`-ээр дуусахад тэр хоёр алга болж, оронд нь үр дүн нь байна. Дуудагчийн хувьд дуудлага бол `add` шиг хэдэн утгыг нэг болгодог л команд.

Энэ нь дуудлага бүр ижил stack дээр өөрийн **[[stack frame|stack-frame]]**-тэй байдгаас ажилладаг. `f` эхлэхдээ хожим хэрэгтэй хоёр зүйлийг хадгална: хаашаа буцах, дуудагчийн frame; дараа нь local-уудад зай гаргана. **FP** регистр frame-ийг заадаг тул `local 0` үргэлж FP + 0-д, аргументууд хадгалсан үгсийн яг дээр байна. Өөр нэг регистр, **[[stack pointer|stack-pointer]]** (SP) үргэлж stack-ийн оройг заана. `f` буцахдаа үр дүнгээ эхний аргумент байсан газар тавьж, SP ба FP-г сэргээгээд буцах хаяг руу үсэрнэ.

Дуудлага бүр өөрийн frame-тэй тул функц өөрийгөө дуудаж болно: энэ бол **[[рекурс|recursion]]**. Демоны factorial-д `fact(3)` нь `fact(2)`-ыг, тэр нь `fact(1)`-ийг дуудна: ижил функцийн гурван frame, тус бүр өөрийн `arg 0`-той, нэг нэгнийхээ дээр овоологдоно. Frame-д юу хаана байх, аль регистр юуг илэрхийлэх нь `docs/VM.md` дахь **[[calling convention|calling-convention]]**. Хөрвүүлэлтийн хэсэг бүр үүнийг дагадаг бөгөөд ингэснээр нэг командын таны хөрвүүлэлт өөр командын суурилуулсан translator-ын хөрвүүлэлттэй зэрэгцэн ажиллаж чадна.

## Stack-аас регистр рүү

Translator нэг удаад нэг командтай ажиллана. Ихэнх команд гурваас найман заавар болно. Жишээ нь `add`:

```
LOAD  r1, [r6]        ; b = орой (r6 бол SP)
ADDI  r6, 1           ; pop
LOAD  r0, [r6]        ; a = шинэ орой
ADD   r0, r0, r1
STORE r0, [r6]        ; нийлбэр a-гийн оронд
```

`mul`, `div`, `mod` нь translator програмд нэмдэг хоёр дэд програмыг дууддаг. Хоёртын тооллоор үржих нь зөвхөн 0 ба 1-тэй багана үржвэр: нэг тооны 1 бит бүрд нөгөө тоог байранд нь шилжүүлж нэмнэ. Хуваах нь багана хуваах: нэг удаад нэг битийг буулгаж, багтах газар бүрт хасна.

Үнэ нь харагдаж магадгүй: утга бүр RAM руу очиж буцдаг, гэтэл гараар бичсэн ассемблер үүнийг регистрт хадгалах байсан. Жинхэнэ системүүд энэ зөрүүг хөрвүүлэгчид илүү ажил хийж, жишээ нь **register allocation**-аар хаадаг. Манайх энгийн хэвээр, төв процессорын хурдан загвар тоглоомд хангалттай хурдан.

VM-ийг шууд ажиллуулж болох тодорхойлолт бас бий: демонд ашигладаг **[[интерпретатор|interpreter]]** хөрвүүлэхийн оронд алхам бүрд нэг командыг гүйцэтгэнэ. Жишиг translator-ын шалгалтууд хэдэн зуун санамсаргүй програмыг хоёр аргаар ажиллуулж, тохирч байгааг шалгана.

## Виртуал машин хаанаас гаралтай вэ

Stack machine анх жинхэнэ техник хангамж байсан. 1961 онд тайлбарласан, ассемблерийн биш ALGOL-оор бичсэн програмд зориулсан Burroughs B5000 бүх арифметикээ stack дээр хийдэг байсан тул заавар нь регистр эсвэл түр байрлалыг огт нэрлэх шаардлагагүй байв[@burroughs-b5000]. Арван жилийн дараа Цюрихийн ETH дэх Никлаус Виртийн багийн Pascal хөрвүүлэгч Pascal-P хэлбэрээр тархсан: виртуал stack machine-ий p-code гаргадаг хөрвүүлэгч ба түүний интерпретатор. Pascal-ыг шинэ компьютерт шилжүүлэхэд зөвхөн тэр интерпретаторыг бичих хэрэгтэй байв. 1977 онд гарсан UCSD Pascal энэ санаан дээр зөөвөрлөх боломжтой бүтэн систем бүтээсэн[@pascal-p-code]. Java Virtual Machine програмуудыг ижил аргаар ажиллуулдаг: method дуудлага бүр local хувьсагчид ба operand stack-тэй frame авч, `iadd` зэрэг заавар operand-уудаа pop хийж, үр дүнг push хийнэ[@jvm-operand-stack]. 2019 оны 12-р сард W3C Recommendation болсон, томоохон хөтөч бүрт ажилладаг WebAssembly ч тооцооллын загвараа stack machine гэж тодорхойлдог[@webassembly-stack].

## Юу бүтээв, юу сурав

**Юу бүтээв:** stack machine-ий командуудыг функц, рекурс, үржих ба хуваах дэд програмтайгаар ассемблер болгодог VM translator; мөн компьютерийн тань дэлгэц, гар дээр ажилладаг VM програмууд.

**Юу сурав:**

- Виртуал машин бол техник хангамжид биш, баримт бичигт тодорхойлогдсон машин; translator эсвэл интерпретатор түүнийг тухайн төв процессор дээр бодит болгоно.
- Stack machine operand-уудаа stack-ийн оройгоос авч, үр дүнгээ push хийдэг тул илэрхийлэл утга ба үйлдлүүдийнхээ дарааллаар хөрвөнө.
- Функцийн дуудлага бүр stack frame авдаг (буцах хаяг, дуудагчийн frame pointer, local-ууд) тул функцууд бие биенээ болон өөрийгөө дуудаж чадна.
- Calling convention бүх зүйл хаана очихыг тогтоодог тул тусад нь хөрвүүлсэн хэсгүүд хамтран ажиллана.

**Дараа нь:** 7-р бүлэгт бид хамтдаа жижиг програмчлалын хэл зохиож, түүнийг VM код болгодог хөрвүүлэгчийг бичнэ.

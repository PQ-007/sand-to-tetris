VM-тэй болсноор програмууд регистрийн талаар бодохоо больсон ч ганц ганц stack командаар бодсоор байна: хоёр хувьсагч нэмэхэд дөрвөн мөр. Хүмүүс `score = score + lines * 10;` гэж бичээд командуудыг програмаар гаргуулахыг хүсдэг. Үүнийг **[[дээд түвшний хэл|high-level-language]]** гэдэг бөгөөд түүнийг доод түвшний код болгодог програм бол **[[хөрвүүлэгч|compiler]]**. Хэлийг та зохиосон: нэр нь C Shard. Энэ бүлэгт та үүнийг сурч, хөрвүүлэгч түүнийг хэрхэн уншдагийг үзээд, дараа нь тэр хөрвүүлэгчийг өөрөө бичнэ.

## C Shard

```
// 1 + 2 + ... + n-ийн нийлбэр.
fn sum(n: int) -> int {
    var total = 0;
    for i in 1..n + 1 {
        total = total + i;
    }
    return total;
}

fn main() -> int {
    return sum(10);
}
```

Энэ нь C ба түүний дараах хэлнүүдтэй төстэй, учир нь бид ингэж сонгосон: блок нь хаалт `{ }` дотор, statement-ийн дараа `;`, хоосон зай ба шинэ мөр хамаагүй. Бүтэн тодорхойлолт нь `docs/LANGUAGE.md`. Бидний хамтдаа хийсэн сонголтууд:

| Асуулт | Бидний сонголт | Яагаад |
|---|---|---|
| Синтакс | хаалттай, C-ийн гэр бүл | танил, програмаар уншихад хамгийн хялбар төрөл |
| Төрөл | `int`, `bool` ба массив, код гаргахаас өмнө шалгана | `if 5 { }` эсвэл bool-ыг тоонд нэмэхийг мөрийн дугаартай нь барина |
| Массив | хөрвүүлэх үед мэдэгдэх тогтмол хэмжээтэй | санах ойн менежер хэрэггүй; Tetris-ийн талбайд хангалттай |
| Дэлгэц ба товч | `mem[addr]` дурын хаягийг уншиж бичнэ | дараагийн бүлгийн OS-ыг C Shard-аар бичиж болно |
| Логик | нөхцөлд `and`, `or`, `not`; битэд `& \| ^ ~` | хоёрыг андуурахгүй, `and`/`or` эрт зогсоно |
| Давталт | `if`/`else`, `while`, `for i in 0..10`, `break`, `continue` | тоглоомын ихэнх давталт мөр эсвэл баганаар явдаг `for` |
| Бичвэр | `'A'` бол тоо; `"GAME OVER"` бол тогтмол массив | дэлгэц дээр үг гаргахад хангалттай |

Тоглоомд хоёр нарийн зүйл чухал. `and` ба `or` эрт зогсдог: `x < 10 and board[x] == 0`-д x хангалттай бага үед л массивыг уншина; үүнийг **[[short-circuit evaluation|short-circuit-evaluation]]** гэнэ. Мөн бит үйлдлүүд харьцуулалтаас өндөр тул `x & 1 == 0` нь харагдаж байгаагаараа буюу `(x & 1) == 0` гэсэн утгатай.

## Програм унших: token ба мод

Хөрвүүлэгч ассемблер шиг үе шаттай ажилладаг. Эхнийх нь **tokenize** бичвэрийг **[[token]]**-уудад хэрчинэ: `while`, `x`, `<=`, `10`, `{`. Хоосон зай ба тайлбар алга болж, token бүр мөрөө санадаг тул хожмын алдаа түүнийг зааж чадна.

Хоёр дахь нь **parse** token-уудаас **[[syntax tree|syntax-tree]]** бүтээнэ. Мод нь хэсгүүд хэрхэн хамааралтайг харуулна. `2 + 3 * 4`-д `*` нь `+`-ийн доор байна, учир нь үржих нь түрүүлж хийгдэнэ:

Аль үйлдэл гүнд орохыг **[[үйлдлийн дараалал|precedence]]** шийднэ. Манай parser үүнийг **[[recursive descent|recursive-descent]]**-ээр шийддэг: дарааллын түвшин бүрд нэг жижиг функц, тус бүр operand-уудаа авахын тулд дараагийн илүү чанга түвшний функцийг дууддаг. `+`-ийн функц `*`-ийн функцийг дуудаж, `+`-ээ бүтээхээс өмнө `3 * 4`-ийг нэг хэсэг болгон буцааж авна. Parser-ийн бүтэц нь дүрмийг шууд дагадаг тул олон жинхэнэ хөрвүүлэгч ингэж бичигддэг.

## Шалгах: нэр ба төрөл

Мод зөв бүтэцтэй байсан ч утгагүй байж болно: x тоо байхад `x = true;`, байхгүй функцийг дуудах, давталтаас гадуурх `break`. Гурав дахь үе шат болох **[[type checker|type-checker]]** модоор явж, код гаргахаас өмнө эдгээрийг мөрийн дугаартай нь барина. Замдаа тогтмолуудыг бодож (`ROWS * 10` нь 200 болно), бүх зүйл хаана байрлахыг шийднэ: global бүр 0 хаягаас дээш RAM-ийн үгсээ, local хувьсагч бүр функцийн frame дахь дугаараа авна.

## VM код гаргах

Сүүлийн үе шат модоор дахин явж VM команд бичнэ. Илэрхийллийн хувьд энэ нь эхлээд хоёр operand-ыг, дараа нь үйлдлийг хийдэг алхалт: `2 + 3 * 4`-д энэ нь `push 2`, `push 3`, `push 4`, `mul`, `add`. Stack machine яг үүнийг хүсдэг. Энэ таарц нь stack machine хөрвүүлэгчийн түгээмэл бай болдгийн шалтгаан.

Statement-ууд label ба үсрэлт болно:

```
while x < 10 {          label L1
    x = x + 1;          push local 0
}                       push 10
                        lt
                        jumpifnot L2
                        push local 0
                        push 1
                        add
                        set local 0
                        jump L1
                        label L2
```

`and` ба `or` зүүн тал нь аль хэдийн шийдсэн бол баруун талаа үсэрч гарна. Функц `func` болж, параметрүүд нь VM аргумент, хувьсагчид нь VM local болно. Global-ийн эхлэх утгыг `main`-ээс өмнө ажилладаг `_init` жижиг функц хадгална.

## Хөрвүүлэгч хаанаас гаралтай вэ

Грейс Хопперын 1951, 1952 онд UNIVAC I-д зориулж бичсэн A-0 системийг ихэвчлэн анхны хөрвүүлэгч гэдэг ч энэ нь өнөөгийн бидний мэдэх хөрвүүлэгчээс илүү бэлэн кодын хэсгүүдийг холбодог loader шиг ажилладаг байв[@hopper-a0]. Жон Бэкусаар удирдуулсан баг IBM-д бүтээж, 1957 оны 4-р сард IBM 704-д хүргэсэн FORTRAN хөрвүүлэгч хангалттай сайн код гаргасан тул ассемблераар бичдэг програмистууд түүний оронд дээд түвшний хэлийг хүлээн авсан[@fortran-1957]. Манай синтаксын эх болсон C хэл 1969-1973 онд Bell Labs-д ганц өгөгдлийн төрөл нь машины үг байсан B хэлээс үүссэн; хувьсагчдад төрөл өгөх нь анхны өөрчлөлтүүдийн нэг байв[@c-language].

## Юу бүтээв, юу сурав

**Юу бүтээв:** өөрийн зохиосон C Shard хэлний хөрвүүлэгч, дөрвөн үе шаттай, тус бүр өөрийн шалгалттай; мөн өөрийн компьютерийн дэлгэц дээр зурж, гарыг уншдаг тэр хэлээрх програмууд.

**Юу сурав:**

- Хөрвүүлэгч бичвэрийг үе шаттай уншина: token, дараа нь syntax tree, дараа нь шалгалт, дараа нь код.
- Үйлдлийн дараалал модны хэлбэрийг шийднэ; recursive descent дүрмийг түвшин бүрд нэг функц болгоно.
- Type checker алдааг програм ажиллахаас өмнө барьж, хувьсагч бүр хаана байрлахыг шийднэ.
- Модны operand-уудыг үйлдлээс нь өмнө үзэх нь stack machine-ий кодыг шууд өгнө.

**Дараа нь:** 8-р бүлэгт та C Shard-аар үйлдлийн систем бичнэ: зурах, бичвэр, гар, цаг ба санамсаргүй тоо.

</aside>
